# LED POP 1.0.9 (27) UI 상호작용 변경

2026-09-11 후속 소스 변경 기록입니다. 이 문서는 새 빌드 완료 기록이 아닙니다.

## 버전

- Expo 앱 버전을 **1.0.9**로 변경했습니다.
- Android `versionCode`를 **27**로 변경했습니다.
- Settings의 App Version은 `Constants.expoConfig.version`을 읽으므로 **V1.0.9**로 표시됩니다.
- 기존 1.0.8(26) APK/AAB에는 아래 변경이 포함되지 않습니다.

## iPad Watch Ad 버튼

- 원본 `Watch_Ad_Button.png`는 277×56 이미지입니다. iPad의 넓은 폭에 전체 이미지를 단순 확대하면서 양끝 곡률도 늘어나던 경로를 수정했습니다.
- iOS에서는 상하좌우 27px `capInsets`를 적용해 양끝 모양을 고정하고 가운데 영역만 늘립니다.
- 버튼 컨테이너는 높이 56 기준 반지름 28과 모서리 클리핑을 적용합니다.
- Android는 기존 `expo-image` 렌더링을 유지합니다. 광고 준비 상태, 활성 조건, 탭 처리 및 광고 표시 순서는 변경하지 않았습니다.

## iPad 사진 불러오기 버튼

- 32×32 버튼에 상하좌우 6px `hitSlop`을 추가하여 유효 터치 영역을 44×44로 확대했습니다.
- 배경 설정 `ScrollView`에 `keyboardShouldPersistTaps="handled"`를 적용해 남아 있는 키보드가 첫 버튼 탭을 소비하지 않도록 했습니다.
- 사진 권한 요청, 편집, 품질 및 배경 저장 방식은 유지합니다.

## 공통 설정 슬라이더

- controlled 값 갱신마다 thumb 이동을 다시 애니메이션하던 `animateTransitions`를 제거했습니다.
- 공통 `step`을 Slider에도 직접 전달하여 드래그 값과 저장 값의 간격을 일치시켰습니다.
- Slider 조작 영역 높이를 48로 확보했습니다.
- 최초 화면 폭으로 고정하던 트랙 폭을 제거하고 `flex: 1`로 현재 사용 가능한 폭을 사용합니다. 폰·태블릿 및 화면 크기 변경에 대응합니다.
- minus/plus 버튼, 값 범위, 값 표시 및 설정 저장 콜백은 유지합니다.

## 검증 범위

JSON 구문과 Git diff 공백 오류를 정적으로 확인했습니다. 컴파일·린트·테스트·새 APK/AAB·iPad 실기기 검증은 실행하지 않았습니다. 실제 iPad에서는 Watch Ad 양끝, 사진 버튼 첫 탭, 각 설정 슬라이더의 누름·드래그·해제 동작을 새 빌드로 확인해야 합니다.

## iPad 슬라이더 드래그 후속 수정

- 1.0.9(27) 출시 산출물 생성 이후 iPad에서 드래그가 잘 시작되지 않거나 끊긴다는 제보에 대응한 소스 변경입니다. 기존 APK/AAB에는 포함되지 않습니다.
- 공통 Slider는 드래그 시작 값을 보관하고, 드래그 중 value prop을 고정하여 상위 설정 갱신이 내부 thumb 위치를 반복 재설정하는 경로를 차단합니다. onValueChange는 계속 전달하므로 설정 값과 숫자 표시는 실시간으로 갱신하고, 드래그 종료 시 외부 값 동기화를 재개합니다.
- Text, Background, Effects의 ScrollView에 directionalLockEnabled, delaysContentTouches=false, canCancelContentTouches=false를 적용했습니다. Text와 Effects에도 keyboardShouldPersistTaps="handled"를 적용했습니다.
- Size의 Pro 잠금, 값 범위와 step은 유지합니다. 잠금 표시 상태의 Size는 의도적으로 조작할 수 없습니다.
- 라이브러리와 앱 소스에서 확인한 값 재설정 및 iOS 터치 취소 경로를 보완한 것입니다. 실제 iPad에서 원인이 재현되거나 개선 효과가 확인된 결과는 아닙니다.
- 이번 후속 변경에서는 빌드·린트·테스트를 실행하지 않았습니다. 다음 승인된 iPad QA에서는 트랙/손잡이 누르기, 양방향 드래그, 해제 시 위치, 세로 스크롤 및 버튼 영역에서 시작하는 드래그, 키보드 표시 상태와 Pro 잠금/해제를 확인해야 합니다. iPhone·Android 회귀 확인도 남아 있습니다.

## 전체 기기 슬라이더 반응 후속 개선

- 공통 슬라이더 손잡이는 연속 좌표로 이동하고 설정 값은 기존 minimumValue 기준 step과 정수 범위에 맞춰 전달합니다.
- 동일 설정 값에 머무르는 이동 이벤트는 중복 전달하지 않아 미리보기의 불필요한 설정 갱신을 줄입니다. 값이 달라지면 드래그 중 즉시 전달하며 지연 타이머는 추가하지 않습니다.
- 종료 콜백에서도 최종 값을 반영하고 손잡이를 저장 값에 정렬합니다. 시작 값과 종료 값이 같은 작은 드래그도 동기화합니다.
- iPhone/iPad/Android의 공통 컴포넌트에 적용되는 소스 변경입니다. 실제 반응 시간·프레임 개선량은 미측정이며 빌드·린트·테스트는 실행하지 않았습니다.


## 스크롤·시작 오류·저장 보호 후속 수정 — 2026-09-12

- 위 iPad 후속 변경의 `canCancelContentTouches=false`는 세로 스크롤을 막을 수 있어 Text·Background·Effects 모두 true로 수정했습니다.
- 공통 슬라이더는 기존 트랙·손잡이 렌더링을 유지하고 터치 판별만 `ScrollFriendlySlider`에서 처리합니다. 누름 즉시 터치를 점유하지 않고, 6 논리 픽셀을 넘는 가로 우세 이동에서만 값 조절을 시작합니다. 먼저 세로 이동한 제스처와 다중 터치는 값 조절을 시작하지 않습니다. 가만히 누른 트랙 탭, 기존 범위·step·Pro 잠금은 유지합니다.
- 저장 설정의 읽기·JSON 파싱·슬롯 배열 검증 실패 시 기본 슬롯 저장 및 자동 저장 활성화를 하지 않습니다. 기존 저장값을 유지하고 현지화된 오류 화면에서 수동 재읽기를 제공합니다. 저장값이 없는 최초 실행만 초기 프리셋을 사용합니다. 손상된 데이터의 자동 삭제·초기화는 제공하지 않습니다.
- 네이티브 스플래시 숨김 실패 시 개발 로그만 남기던 경로에 현지화된 네이티브 오류 안내와 수동 재시도를 추가했습니다. React 오류 화면도 제공하며 숨김 성공을 조작하거나 자동 반복 재시도하지 않습니다.
- 검증 범위: 소스와 diff 정적 검토만 수행. 빌드·린트·테스트·실기기 검증 미실행. 새 배포본에 포함됐다는 의미가 아닙니다.
- 다음 승인된 검증: iPhone/iPad에서 세 탭 마지막 버튼까지 접근, 트랙·손잡이·잠금·여백에서 세로 드래그, 가로 조절과 탭·해제·다중 터치·취소, 키보드 표시 및 Android 회귀. 저장 읽기 실패/잘못된 JSON에서 원본 유지와 성공적인 수동 재읽기, 스플래시 실패 시 네이티브 안내 실제 표시와 재시도 성공도 확인해야 합니다.


## 스플래시 → 메인 초기 표시 순서 개선 — 2026-09-14

- 재설치한 1.1.0(28) APK의 연결 기기 녹화에서 로딩 로고 사이의 어두운 화면과 메인 공개 뒤 미리보기 글자·선택 폰트가 뒤늦게 표시되는 현상을 확인했습니다. 이전의 지속적인 검은 화면과 같은 원인으로 확정한 것은 아닙니다.
- 설정 제공자와 루트가 각각 만들던 React 로딩 화면을 루트의 단일 오버레이로 통합했습니다. 저장 설정 복원이 끝나야 자식을 마운트하는 보호는 유지하며, 복원 실패 안내와 수동 재읽기도 루트에서 제공합니다.
- 네이티브 스플래시는 투명 이미지 대신 기존 POP 로고를 사용하도록 설정하고 배경색·로고 폭을 React 로딩 화면과 맞췄습니다. React 로딩 화면의 배치와 이미지 로드(실패 시 오류 화면)를 준비한 뒤 네이티브 화면을 닫습니다. 로고는 중앙에 고정하고 로딩 점은 그 아래에 배치했습니다.
- 750ms 강제 대기를 제거했습니다. 메인을 오버레이 뒤에 먼저 마운트하고 저장 설정, UI 폰트, 화면 배치, 홈 미리보기의 요청 폰트와 텍스트 그리기 데이터가 준비되면 두 프레임 경계 뒤 오버레이를 제거합니다. 빈 문구와 그릴 수 있는 글리프가 없는 문구도 편집 화면 진입을 막지 않으며 다른 경로로 직접 진입할 때는 홈 미리보기를 기다리지 않습니다.
- 준비 중인 메인은 터치·접근성 탐색 대상에서 제외하고 공개 후 정상적으로 활성화합니다. 완료 상태는 앱 실행 중 유지되어 이후 탭 이동·글자 편집·폰트 변경 때문에 시작 화면을 다시 띄우지 않습니다.
- 폰트 캐시는 요청한 자산과 실제 로드한 자산을 함께 추적하여 이전 폰트를 새 폰트의 준비 완료로 오인하지 않게 했습니다. 저장 데이터나 성공한 폰트 캐시를 삭제하지 않습니다.
- UI 폰트/로딩 이미지 실패 및 전경에서 30초 동안 준비가 끝나지 않는 경우 오류와 수동 재시도를 제공합니다. 시간 경과를 성공으로 처리하거나 불완전한 메인을 강제로 공개하지 않습니다. 재시도는 실패한 Skia 캐시만 해제하고 화면 준비를 다시 시작하며, 설정 제공자·프리미엄·루트 광고 수명 주기는 재마운트하지 않습니다. 네이티브 스플래시 숨김 실패의 별도 안내·재시도도 유지합니다.
- 이번 변경은 소스와 diff 정적 검토 범위입니다. 빌드·린트·테스트와 수정본 실기기 검증은 실행하지 않았고 기존 APK/AAB에는 포함되지 않습니다. 다음 승인된 빌드에서는 변경된 스플래시 네이티브 설정을 반영해야 하며 기존 네이티브 출력을 그대로 재사용하면 안 됩니다.
- 수정본 검증 시 첫 설치/저장 설정 복원/빈 문구/저장한 원격 폰트/Pixel 효과/직접 경로 진입/준비 중 백그라운드 복귀 및 오류 재시도를 확인합니다. 정상 공개 후 세 탭 스크롤·버튼·미리보기·광고 회귀 확인이 남아 있습니다.


## 시작 초기화 분산·가려진 효과 일시정지 — 2026-09-14

- 첫 화면에 필요한 UI/저장 언어 폰트·선택 미리보기 폰트와 기존 화면 준비 조건을 유지합니다. 추가 폰트 사전 로드는 메인 공개 후 idle 시점부터 진행하며, RN 폰트는 최대 두 family씩, Skia는 한 자산씩, 원격 폰트는 한 세트씩 순차 처리합니다. 이미 로드된 RN 폰트와 기존 Skia/다운로드 캐시·진행 중 요청을 재사용합니다.
- 선택적 작업 큐는 한 작업이 끝난 뒤 다음 idle 시점을 예약합니다. 백그라운드 진입 시 대기 예약을 취소하고 복귀하면 남은 작업을 이어갑니다. 이미 시작된 다운로드/디코딩은 중도 폐기하지 않습니다. 선택적 작업 실패는 기존 개발 로그에 기록하며 준비 성공을 조작하지 않습니다.
- 루트 광고 시작·Settings 요청·광고 재시도/보상 처리, 프리미엄 확인, 분석 식별/수집, 저장 보호 및 입력·스크롤 경로는 이번 최적화에서 변경하지 않습니다.
- 기존 `usePlaybackActive`의 화면 포커스·전경·미리보기/전체화면 조건에 시작 오버레이 공개 여부를 추가했습니다. 오버레이 뒤에서도 준비에 필요한 폰트·배치 계산은 계속되며 애니메이션 생성만 대기하므로 준비 완료와 재생 시작이 서로 기다리지 않습니다.
- 일반/Pixel 미리보기와 전체화면의 모든 그라데이션에 활성 상태를 전달했습니다. 가려지면 반복 애니메이션을 취소하고, 같은 컴포넌트·프리셋으로 복귀하면 보관한 위상과 남은 시간으로 이어갑니다. 프리셋 변경 시 초기화하는 기존 동작과 주기·색상·해상도는 유지하며 unmount 시에도 애니메이션을 정리합니다.
- Effect 1 배경 프레임 타이머는 일시정지 때 다음 프레임까지 남은 시간을 보관합니다. 복귀 시 현재 프레임에서 이어지고 이후 주기는 기존 260ms입니다. 마퀴·Blink·Heart의 기존 재개 계산은 변경하지 않습니다.
- 검증은 소스/diff 정적 검토만 수행했습니다. 빌드·린트·테스트·실기기 성능 측정은 실행하지 않았습니다. 새 APK/AAB에 반영되지 않았으며 프레임·메모리·시작 시간 개선 수치는 미측정입니다. 다음 승인된 QA에서 저장 언어가 기기 언어와 다른 시작, 로컬/원격 폰트·빈 문구, 일반/Pixel 그라데이션, Settings 이동, 전체화면 전환, 앱 전경 복귀와 효과 재개, 광고 및 스크롤 회귀를 확인해야 합니다.

## 설정 탭 세로 스크롤·iPad Watch Ad 배경 후속 수정 — 2026-09-14

- 앞선 `canCancelContentTouches` 수정은 자식 컨트롤에서 시작한 세로 제스처를 ScrollView가 인계받는 경로만 보완했습니다. 컴포넌트 분리 후 Text·Background·Effects의 각 ScrollView에 높이 제약이 빠져 콘텐츠 전체 높이로 측정된 뒤 부모에서 잘렸고, 내부 스크롤 거리가 생기지 않는 공통 레이아웃 원인이 남아 있었습니다.
- 세 ScrollView 모두 기존 `settingsPanelContainer`를 적용해 남은 편집 화면 높이 안에서 `flex: 1` 뷰포트를 갖게 했습니다. 각 탭의 콘텐츠가 뷰포트를 넘으면 독립적으로 상하 스크롤됩니다. 기존 탭 전환, 슬라이더의 가로 조작 판별, 키보드 탭 처리, 설정값 및 Pro 잠금 동작은 변경하지 않았습니다.
- 리워드 팝업의 Watch Ad 배경 이미지는 절대 배치에 더해 너비와 높이를 각각 `100%`로 명시했습니다. iPad에서 이미지가 버튼 전체를 채우지 못하고 일부만 표시되는 레이아웃을 막으며, 기존 56 높이·28 반지름·capInsets·문구·터치 영역과 광고 준비/표시 순서는 유지합니다.
- 소스와 문서 diff만 정적으로 확인했습니다. 요청에 따라 빌드·린트·테스트는 실행하지 않았고 iPhone/iPad 실기기 스크롤 및 Watch Ad 표시도 아직 검증하지 않았습니다. 기존 APK/AAB에는 이번 수정이 포함되지 않습니다.
